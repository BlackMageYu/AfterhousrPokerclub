# 原生架构与内部通信

基线：2026-09-07，4.0.0。

## 1. 运行结构

```text
AfterHours.exe（C# / WPF）
  ├─ 原生大厅、牌桌、弹窗、声音、复盘
  └─ RulesClient
       │ 标准输入 / 输出：每行一条 JSON
       ▼
runtime/rules.exe native/bridge.mjs [可选数据根目录]
  └─ bridge 串行调度
       └─ AIGameService
            ├─ GameStore → HoldemEngine / 本地 Bot / 人物与世界
            └─ 可选外部 AI 请求 → 本地合法性检查 → 行动或回退
```

`runtime/rules.exe` 是随包携带并重命名的 Node.js 运行时，不是另一个 C# 游戏核心。它不创建浏览器窗口，也不作为本地 HTTP 服务运行。远程网络仅用于用户主动配置的外部 AI 功能。

WPF 中的 `Canvas`、控件模板和 XAML 属于原生控件体系，不是 HTML Canvas 或网页模板。`System.Web.Extensions` 在这里提供 JSON 序列化器，也不表示客户端加载了网页。

## 3. 消息协议

请求一行一个 JSON；末尾换行是消息边界。

```json
{"id":1,"command":"state","body":null}
```

成功和失败分别返回：

```json
{"id":1,"value":{"app":"afterhours-poker"}}
{"id":2,"error":"牌局已更新，请以当前牌局为准"}
```

以上 `value` 仅演示结构，真实状态包含账户、世界、场次等字段。

- C# 用 `SemaphoreSlim(1,1)` 保证同一时刻只有一个未完成的管道请求。
- 每次请求递增 `id`，读取响应时校验 ID 一致性。
- Node 端用 Promise 链串行执行命令，避免状态交错修改。
- 桥接层将 `body: null` 归一化为 `undefined`，兼容查询分支。
- stdout 只写协议 JSON；调试日志应写 stderr 或文件，不要往 stdout 插入普通文字。
- bridge 对单行长度设有上限，当前比较的是 JavaScript 字符串长度，不能把它误称为精确字节上限。
- 当前协议没有显式版本字段；后续升级时建议增加版本协商。

## 4. 命令分类

| 类型 | 主要命令 |
| --- | --- |
| 查询 | `state`、`contacts`、`archives`、`archive?session=...`、`history?session=...&hand=...` |
| 牌局 | `start`、`action`、`tick`、`next`、`show`、`extend`、`timeout`、`end` |
| 账户 | `rebuy`、`cashout`、`claim-daily`、`profile-settings` |
| 原生适配 | `pause`、`mark`、`key-init`、`shutdown` |
| 设置 | `ai-settings`、`ai-test`、`ai-cancel`、`music`、`export` |

命令名中保留 `?session=...` 是沿用本地查询参数解析方式，不会因此发起网页请求。新增命令需要同时考虑 bridge 白名单、服务层处理、UI 状态更新和测试。

## 5. 行动一致性与调度

`MainWindow.Turn()` 携带三项校验数据：

- `sessionId`：当前场次。
- `handNumber`：当前手牌。
- `eventCount`：当前事件数。

规则层拒绝旧场次、旧手牌或旧事件版本发出的行动。UI 的 `busy` 控制、管道锁和规则层版本检查互相配合；不能用“按钮禁用”代替最终合法性检查。

`Pulse()` 使用约 250 ms 的 DispatcherTimer：

1. 更新房间与玩家倒计时文字。
2. 忙碌、暂停或打开弹层时停止自动推进。
3. 玩家行动到时提交 `timeout`。
4. 电脑行动每隔至少约 500 ms 检查一次；传入 `botTiming: true` 保留表现上的思考时长。
5. 行动后约 2 秒缓冲，避免快速连点和下一轮误操作。
6. 结算后默认约 5 秒开始下一手，主动阅读复盘时可停留。
7. 大厅按分钟量级请求状态；世界的实际工作、休息、后台牌局补算仍由世界模块负责。

需要注意：弹层暂停自动推进，与点击“暂停牌局”并不完全相同；后者会在规则层保存暂停状态并调整行动截止时间。相关边界见后续清单。

## 6. 暂停、关闭与恢复

- 暂停：保存 `nativePaused` / `nativePausedAt`；继续时平移玩家行动时间和机器人思考时间。
- 房间 `expiresAt` 不因暂停自动顺延，仍属于现实经过时间。
- 普通关闭窗口：尝试清除暂停状态，发送 `shutdown`，保存并退出；下次打开读取原场次。
- “结束本场/强制退出”：收尾当前手，写报告并结算筹码回到账户。
- 客户端销毁规则进程时先关闭 stdin，并短暂等待；仍不退出时才终止自己的子进程。
- C# 请求若发现进程退出、响应 ID 错乱或输出中断，会转为错误提示。当前没有自动拉起规则进程的完整恢复机制。

## 7. 新增功能的最短路径

以“增加一种账户操作”为例：先在 Store 实现资金语义和校验，再通过 bridge 开放命令；WPF 仅负责输入与呈现。补充资金不变量测试与管道错误场景，最后查看真实渲染效果。不要直接在 C# 中修改账户 JSON 来绕过业务层。
