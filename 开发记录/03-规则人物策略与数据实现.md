# 规则、人物、策略与数据实现

基线：2026-09-07。本文中的金额指游戏美元筹码口径，代码按整数处理。

## 1. 规则核心与修改入口

| 模块 | 职责 |
| --- | --- |
| [cards.js](../src/cards.js) | 52 张牌、洗牌、5–7 张牌力评价、最佳五张牌提取 |
| [engine.js](../src/engine.js) | 发牌、行动权、街道推进、盲注、Straddle、底池与边池、结算、座位生命周期 |
| [store.js](../src/store.js) | 账户与牌桌资金、场次时长、保存恢复、补助、报告和历史查询 |
| [bot.js](../src/bot.js)、[styles.js](../src/styles.js) | 可见观察对象、风格化策略与思考时间 |
| [report.js](../src/report.js) | Markdown / JSON 牌局报告 |

牌用两字符标识，例如 `As`、`Th`：点数 `23456789TJQKA`，花色 `s/h/d/c`。`evaluate()` 返回可比较的牌力，`bestFive()` 枚举组合得到实际参与成牌的五张牌。复盘高光应使用 `rank.cards`，不要按牌型名称自行推断。

关键规则保持在 `HoldemEngine` 内：最小完整加注、短全下是否重开加注权、有效跟注金额、无人跟注部分退回、分层边池资格和平分余数。UI 只读取 `legal`，不能另写一套独立判定。

五档盲注为 1/2、5/10、25/50、100/200、500/1000；人数为 2/3/5/7，带入为 50–500 BB。`raise` 的金额是“本街加注到”的总额，不是这次额外投入额。

## 2. 状态流与事件快照

一手牌按翻牌前、翻牌、转牌、河牌、摊牌或提前获胜推进。每个阶段按引擎规则烧牌和发牌。引擎事件保存街道、公共牌、行动者及执行后的筹码快照。

```text
输入命令 → 校验场次/手牌/事件版本 → legal 校验
        → 执行动作 → 记录事件及 snapshot
        → 必要时推进街道或结算 → 保存 → 返回公开状态
```

回放使用保存的事件，不重新运行机器人。当前牌桌的 `view()` 隐藏不应公开的底牌；事后牌谱与机器人观察对象不能混用。

`finalPot` 在结算时保存各主池/边池金额总和。当前手状态结束后，显示最终底池应优先使用它，避免把已发给赢家、当前剩余为零的资金当作本手总底池。

## 3. 资金记账：特别容易再次出错的地方

### 账户与桌上筹码是不同账本

开桌从账户扣除带入；中途补码继续从账户扣除；中途退码增加账户；最终下桌只回存仍留在桌上的筹码。奖金、底池返还、补码和退码含义不同。

### 场次净盈亏

```text
场次净盈亏 = 最终桌上筹码 + 累计中途退码 totalCashOut - 累计带入 totalBuyIn
```

若只用“最终桌上筹码 − 累计带入”，玩家把赢来的钱提前退到账户，会被错误记成输掉。`store.js` 的场次总结与 `report.js` 的报告口径已同步修正。

### 单手净盈亏

```text
stackAdjustments[座位] = 本手补入金额 - 本手退回金额
本手净盈亏 = 结束筹码 - 开始筹码 initialStacks - stackAdjustments
```

补码/退码不改变已经进入底池的投入；它们记入 `movements`，并在进行中的牌局更新 `stackAdjustments`。例如带入 200、补到 300、中途退 50 后弃掉小盲，本手仍只亏实际小盲，不会把资金搬动当输赢。

回归入口：[native-accounting.test.js](../tests/native-accounting.test.js)。以后新增奖励、买保险、抽水或结算单位时，应先写清账本变化，再修改显示文案。

## 4. 人物、头像、统计与竞猜

| 模块 | 维护内容 |
| --- | --- |
| [roster.js](../src/roster.js) | 本地与 AI 角色池、身份选择、财务资料 |
| [role-library-index.js](../src/role-library-index.js)、`role-library*.js` | 人物原始资料与背景故事 |
| [player-cards.js](../src/player-cards.js) | 从资料构造固定的牌手参数与 level |
| [character-profiles.js](../src/character-profiles.js) | 永久牌风、档案分段、头像描述符 |
| [career.js](../src/career.js) | 长期统计的合并与保存 |
| [memory.js](../src/memory.js) | 公开牌局记忆及其策略影响 |
| [discovery.js](../src/discovery.js) | 竞猜票据、公开程度、资料投影与报告脱敏 |

实际总角色数为 155：38 位本地牌友、117 位 AI 牌友；AI 池包括 10 位传奇牌手原型。人物数值用于规则进程决策，UI 不展示具体 level、松紧、纪律、诈唬等私有参数。

长期统计包含 hands、vpip、pfr、won、showdowns、maxWon。牌桌档案按已玩手数计算 VPIP/PFR 百分比。当前 `maxWon` 来源是历史单手获奖金额的最大值；它不是已经减掉该手投入后的最大净利润，修改文案或统计时要留意这个区别。

预估形象保存在 `profile.marks[characterId]`，不消耗竞猜次数。正式竞猜必须完成至少一手并下桌后持有本场 ticket，每位对手本场仅一次。

完整公开条件：

```text
correct >= 2
或 correct >= 1 且 wrong >= 2
或 wrong >= 3
```

接口不直接返回猜对/猜错字段。档案在完整公开前还会按尝试次数渐进显示前面的分段；不要把“完整公开前完全看不到任何资料”写成当前行为。

## 5. 机器人策略与生命周期

本地 Bot 采用人物风格、位置、底池赔率、有效筹码、公开行动记忆和未知牌抽样估计决策，不是经过证明的 GTO 求解器。原生重建没有把机器人策略替换为一组固定行动按钮概率。

普通模式保留约 1–10 秒表现型思考时长；玩家弃牌后可快速完成剩余机器人行动，规则事件仍然保存，快速阶段跳过相应语音和筹码表现。

本次补充的生命周期：

- 输光后根据水平生成 10%–30% 的离开倾向；有足够后手资金且决定继续时，设置 `reloadPending`。
- 只有满足至少 50 BB 的资金条件才能按该路径补码，并从人物后手资金中实际扣除。
- 补码、替换身份发生在两手之间。
- 空位以当前固定 40% 概率尝试补人，处于文档要求的 30%–50% 范围内。
- 新人物选择排除仍在桌上的身份，避免一张桌子出现同一个角色的两个座位。
- 同时挂机人数上限：七人桌 3、五人桌 2、三人桌 1、单挑 0。
- 挂机会设置返回手数；它与资金离桌后的空座不同。

长期统计需要按 `characterId` 追踪，不能以 `seatId` 当作永久身份。后续改动补位逻辑时应额外检查离开人物的最后统计是否已在被替换前同步。

## 6. 世界状态与存档

[world.js](../src/world.js) 与 [schedules.js](../src/schedules.js) 按日程推进工作、休息、后台牌局；在线状态由日程与资金条件决定。状态查询可能补算此前经过的时间，不是简单生成随机“在线人数”。

| 文件 | 内容 |
| --- | --- |
| `.poker-data/state.json` | 账户、当前场次/引擎、身份竞猜、职业统计、记忆 |
| `.poker-data/world.json` | 角色日程与后台世界记录 |
| `.poker-data/ai-settings.json` | API 地址、模型、等待时间、加密密钥字段 |
| `native-settings.json` | 本地头像路径、声音、字号、音乐开关和音量 |
| `.poker-data/player-avatar.png` | 原生头像上传后转换的本地图片 |
| `日志/poker-session-*.md/.json` | 已结束场次报告 |

Store 通过“写入 `.tmp` 后 rename”降低单个 JSON 写到一半的风险。多个文件之间还没有完整事务或统一代际提交机制；不能据此宣称掉电时一定同时恢复到同一版本。

进行中手牌恢复使用 `HoldemEngine.restore()`；不可恢复的手牌通过退款/作废记录退出损坏状态。账户 JSON 本身完全无法解析是另一类问题，当前并没有覆盖所有损坏类型的自动恢复。

## 7. 外部 AI 接口

[external-ai.js](../src/external-ai.js) 构造每个座位独立的观察对象，只发送自己的底牌及公开信息；模型回复必须通过本地 `validateDecision()`。超时、网络错误、错误格式、不合法行动和超大响应会触发本地接管。

[ai-settings.js](../src/ai-settings.js) 规范化地址、模型、超时和 Key。远程接口使用 HTTPS，本机模型允许 loopback HTTP。

WPF 用当前 Windows 账户的 DPAPI 加密 Key，桥接层把密文存盘，明文仅在运行中用于请求。旧 Electron 的密文不会自动转换。日志、截图和测试资料不应保存用户真实 Key。

当前管道串行调度意味着外部请求还未返回时，后续取消命令也可能排队；这与 AI 服务内部已经支持 AbortController 是两个不同层面的能力，后续应补充验证和控制通道设计。
