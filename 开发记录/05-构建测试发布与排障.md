# 构建、测试、发布与排障

适用路径：`C:\Users\qq121\Desktop\AfterHours`。以下命令在 Windows PowerShell 中执行。

## 1. 构建

先关闭需要重新编译的那个游戏实例，避免 EXE 被占用。构建入口为 [build.ps1](../native/build.ps1)：

```powershell
Set-Location -LiteralPath 'C:\Users\qq121\Desktop\AfterHours'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\native\build.ps1
```

脚本使用：

```text
C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe
/target:winexe /platform:x64 /optimize+ /utf8output
```

它会编译 `native` 下的 `.cs` 文件，输出根目录 `AfterHours.exe`。这是直接使用 Framework 编译器的构建方式，当前没有 `.csproj` 或 SDK 项目。脚本中 Framework 和 WPF 程序集位置按当前 Windows 环境配置；迁移到其他开发环境时需先核对。

## 3. 原生渲染与流程验收

```powershell
$gameRoot = 'C:\Users\qq121\Desktop\AfterHours'
$qaProcess = Start-Process -FilePath (Join-Path $gameRoot 'AfterHours.exe') `
  -ArgumentList '--qa' -WorkingDirectory $gameRoot -WindowStyle Hidden -PassThru
if (-not $qaProcess.WaitForExit(45000)) { throw 'Native QA timeout' }
if ($qaProcess.ExitCode -ne 0) { throw 'Native QA process failed' }
if (Test-Path -LiteralPath (Join-Path $gameRoot 'qa\failure.txt')) {
  Get-Content -LiteralPath (Join-Path $gameRoot 'qa\failure.txt')
  throw 'Native QA failed'
}
Get-Content -LiteralPath (Join-Path $gameRoot 'qa\result.json')
```

当前 `--qa` 的实际行为：

1. 使用 `qa/data` 作为测试数据根目录。
2. 清理上次 `qa/failure.txt` 与 `qa/result.json`。
3. **重新导出并覆盖 `assets/scenes/table-*.png` 五份场景图。** 因此它不是完全只读的验收工具；如手工替换过这些场景，应先备份，或先改造 QA 把场景导出单独拆开。
4. 展示大厅、开始七人低级桌、推进一手、显示设置/档案、结算与回放。
5. 输出九张界面 PNG 与结果文件，最后关闭规则进程和窗口。

QA 调用原生界面方法并使用真实规则进程，但许多行动由代码直接发命令完成。它不是通过操作系统模拟鼠标逐个点击所有按钮的测试；真人点击、拖动、键盘焦点、实际等待时间、长时间运行和听感需要另外验收。

`result.json` 的写入发生在最终关闭步骤之前。判断通过时还要看是否出现 `failure.txt` 以及进程是否正常退出，不能只看到 `ok: true` 就停止检查。

## 4. 人工回归建议

- 单挑/三人/五人/七人布局；窗口最小尺寸、最大化、全屏、多种 DPI。
- 玩家依次执行弃牌、过牌、跟注、合法加注、短全下、普通全下。
- 预设金额、拖动滑块、直接输入、输入无效金额、点击前后焦点切换。
- 正常 Bot 延时、玩家弃牌后的快速收尾、快速弃牌排队与取消。
- 倒计时到零、每手一次 +20 秒、暂停/继续、弹窗停留后返回。
- 五秒下一手、主动停留复盘、下一手 Straddle、无人可补位时的提示。
- 中途补码/退码后看账户、手牌结果、场次总结与报告是否一致。
- 关闭再开恢复；到时完成最后一手；强制退出没有增加虚构手牌。
- 历史牌手补位前后的名字/头像；回放事件跳转、事后显示全部底牌、高光。
- 有音频设备时实际试听；损坏或缺失音频不应卡住牌局。

## 5. 发布与备份

修改已交付目录之前，备份正常 `.poker-data`、`日志`、`native-settings.json` 和自定义素材；源码备份与存档备份分别管理。更新代码时不要用测试账户覆盖正常账户。

至少需要一起交付 EXE、config、`runtime`、`native/bridge.mjs`、`src`、`assets`。音乐、开发源码和测试文件按本项目的可维护交付方式一并保留。

[deploy.ps1](../native/deploy.ps1) 是首次从固定 `POKER/native-stage` 新建 `Desktop/AfterHours` 的脚本，包含“目标已存在则停止”的保护。它不是通用升级器，不应在后续更新时去掉保护后直接整目录覆盖。

发布后在实际安装路径再跑一次规则测试与原生验收；检查相对路径、资源加载和独立启动，而不只是比较开发目录结果。

`verification/files.json` 是首次复制时生成的文件指纹快照；后续修改、QA 导出或新增文档后不会自动刷新，不能将它当成实时目录清单。

## 6. 常见故障定位

| 表现 | 先检查 |
| --- | --- |
| EXE 无法启动 | 根目录 `startup-error.txt`、Framework/WPF、文件是否齐全 |
| 窗口出现但没有大厅 | 数据根目录 `initialization-error.txt`、规则运行时路径、JSON 解码 |
| 规则进程退出或无响应 | 数据根目录 `rules-errors.log`、stdout 是否混入普通日志、请求是否排队 |
| 界面运行异常 | 根目录 `native-errors.log`，随后定位具体控件与状态 |
| QA 无结果 | 是否看错目录、进程是否结束、初始化日志、是否残留 QA 实例 |
| QA 报错但 result 看似成功 | 看 `qa/failure.txt` 的时间与进程退出状态 |
| 历史回放错人物 | 是否读取了该手 `finalPlayers`，而非场次最终座位人物 |
| 赢亏不对 | 是否漏算 `totalCashOut`、`stackAdjustments`、退款或有效底池 |
| 密钥换电脑不可用 | 当前 Windows 用户是否能解密 DPAPI；旧 Electron Key 需重填 |
| WebP 头像失败 | 本机 WIC 编解码器支持；可先使用 PNG/JPEG |
| 无声音或关闭时异常 | 输出设备、Windows 语音、音频文件格式与失败回退 |

日志可能包含业务诊断信息，分享前应检查内容；不要把真实 API Key 写入诊断输出或开发记录。
