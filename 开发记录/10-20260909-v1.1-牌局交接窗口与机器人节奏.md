# 2026-09-09 v1.1 牌局交接、窗口与机器人节奏

适用版本：v1.1。
目标：消除新一手牌与后台轮询交接时的快速弃牌误报，保证摊牌信息有足够展示时间，并将桌面窗口与机器人行动节奏统一为可预测的体验。

## 1. 快速弃牌与牌局版本交接

快速弃牌以前携带的是按钮绘制时的 `handNumber` 与 `eventCount`。新手牌已经开始、但上一轮后台 `tick` 仍在返回时，这两个字段可能过期，因而出现“牌局已更新，请以当前牌局为准”，需要再次点击。

现将快速弃牌定义为“本桌当前翻牌前手牌的弃牌意图”：

- 保持同一场次才允许执行，绝不会越过换桌或下桌操作；
- 接收到请求时重新读取当前手牌编号与事件数；
- 当前手仍为翻牌前、玩家仍未弃牌且在待行动列表中时，直接对当前手执行快速弃牌；
- 普通弃牌、跟注、加注、亮牌、延时和下一手仍保留严格版本校验，避免旧按钮误操作新牌局。

实现入口：[store.js](../src/store.js)、[external-ai.js](../src/external-ai.js)、[MainWindow.cs](../native/MainWindow.cs)。新增回归测试覆盖经由外接 AI 服务和直接规则层的两种过期快速弃牌路径。

## 2. 结算展示

摊牌完成后，桌面端的自动推进由 `settleAt` 控制。v1.1 将常量 `ResultRevealSeconds` 设为 10 秒，并用于：

- 正常摊牌和非摊牌底池结算；
- 显示赢家头像／手牌、牌型与派奖动画；
- 从局内精简复盘关闭后重新回到结算桌面。

玩家仍可使用“立即下一手”主动跳过等待；打开精简复盘时自动暂停结算倒计时。

## 3. 普通窗口与比例锁定

客户端启动时改为普通、带标题栏的可调窗口，不再默认最大化。通过 Windows 的 `WM_SIZING` 消息在拖拽窗口边缘或角落时保持 16:9 外框比例；F11 无边框全屏与 Esc 返回普通窗口的既有行为保持不变。

比例在窗口改变尺寸的过程中就被约束，因此 WPF 的 `Viewbox` 不会把牌桌、头像或按钮横向／纵向拉伸。

## 4. 机器人可见行动延迟

本地常规机器人本来就采用延迟计划；本次将同一最低展示时间补齐到外部 AI 服务：

- 本地规则直接接管的简单局面至少 1 秒后才落子；
- 外接 API 成功返回后，如总耗时不足 1 秒，补足至 1 秒；
- API 超时或异常由本地托管时同样遵守该下限；
- 玩家行动和显式的快速弃牌／结束本场快速结算不引入这 1 秒。

动作记录的 `thinkTimeMs` 现在也包含该可见等待，便于在牌谱中区分玩家与机器人节奏。
