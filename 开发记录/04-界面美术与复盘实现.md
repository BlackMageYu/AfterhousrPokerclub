# 界面、美术与复盘实现

基线：2026-09-07。

## 1. 视觉需求如何落到代码

最终风格来自用户提供的 WPT 类参考图：绿色俯视椭圆牌桌、木地板、深色座位卡、蓝色渐变操作按钮，以及两行扁平 Logo。静态美术与实时游戏数据分离。

| 层 | 实现 |
| --- | --- |
| 房间与桌面材质 | AI 生成位图，再由原生场景绘制校准 |
| AFTERHOURS / POKER CLUB™ | AI 设计的蓝红叠放扑克牌图标与文字，印在场景材质上 |
| 公共牌与底牌 | WPF Grid / Border / TextBlock 绘制，非背景图中的像素按钮 |
| 头像 | 迁移的本地 JPG，由 ImageBrush 填入圆形控件 |
| 名字、筹码、位置和操作区 | 原生控件，与当前状态同步 |
| 弹窗、档案、复盘 | Grid、StackPanel、ScrollViewer 等 WPF 布局 |

## 2. 牌桌比例与场景坐标

用户参考图为 3832 × 1970；逻辑画布为 **1500 × 771**，由 `Viewbox(Stretch.Uniform)` 等比缩放。宽高比不合适的窗口允许留边，不应通过随意拉伸来填满画面。

| 锚点 | 逻辑坐标 |
| --- | --- |
| 桌面外沿左 / 右 | x = 255 / 1230 |
| 桌面外沿上 / 下 | y = 116 / 563 |
| Logo 中心 | x = 750，y = 340 |
| Logo 横向校准范围 | x ≈ 637.5–862.5 |
| 输出本地场景图 | 3000 × 1542 |

对应实现：[Scene.cs](../native/Scene.cs)。`TableBackground()` 使用非均匀切片采样对齐材质锚点，`ExportScenes()` 导出五份本地场景。若替换美术源，不能假设旧 `sx/sy` 采样数组仍正确。

## 3. 原生控件与布局维护

`Core.cs` 的 UI 工厂统一文字、面板和按钮。按钮使用 WPF ControlTemplate 实现圆角、渐变、悬停、按下与禁用状态。

`Table.cs` 按人数选择座位坐标数组，并分别叠加底牌、头像卡和下注筹码。玩家底牌比电脑牌背更大。当前行动座位使用蓝色边框/发光；弃牌信息降低透明度；过长姓名截断后可打开档案查看。

当前实现偏重可运行迁移：`Render()` 会清理并重建主要界面，而不是成熟的逐控件数据绑定。新交互若需要保持输入焦点、动画进度或滚动位置，应先评估重绘影响。

字号通过 `UI.Scale` 影响主要文字及按钮；部分输入控件仍有固定字号。调整字号后，尤其要验收长姓名、中文换行和最小窗口。

## 4. 人物头像如何从网页图集迁移

[export-portraits.mjs](../native/export-portraits.mjs) 导出 roster 中的身份与头像描述符；[prepare-assets.py](../native/prepare-assets.py) 沿用原头像选择规则，把本地图集拆成原生可加载的文件。

迁移过程保留性别、地区、年龄/场景描述和稳定 slot。专用图集按 4 × 4 单元选择；超出专用图集的身份使用原有分区和稳定 hash 的后备规则。传奇人物使用既有彩色照片。

- `assets/portraits/*.jpg`：最终裁切的人物图。
- `assets/avatar-map.json`：旧描述符到图片文件名的映射。
- `assets/roster-portraits.json`：迁移时的身份/头像清单。

维护经验：一并检查人物身份与图像对应关系，不能只确认“图片能打开”。新增角色后需重新导出映射，已有角色应保持稳定，避免更新后突然换脸。

## 5. 精简复盘：牌桌内速览

入口为 `ShowCompact()`，默认在手牌结束后展示。逐行组织玩家信息，与用户提供的精简复盘图保持相似阅读顺序：

```text
头像 / 姓名 / 底牌 / 牌型
→ 翻牌前摘要 → 翻牌牌面及摘要 → 转牌 → 河牌
→ 净盈亏、投入
```

数据来自当前公开状态 `hand.results`、`hand.events`、`hand.board`。没有公开的对手底牌显示牌背。每个玩家对应的最佳五张牌从 `rank.cards` 取得，使用金色边框和无偏移发光效果高亮。

自动速览默认约 5 秒后下一手；主动打开阅读设置 `reviewHold`。七人桌结果超过面板高度时可滚动。其目标是快速了解结果，不承载每个事件的完整审计内容。

## 6. 详细复盘：只在大厅开放

UI 入口 `ShowReplay()` 在有当前牌桌时退回精简复盘；bridge 还会拒绝在桌期间的 `history...` 查询。这样限制不是只靠隐藏按钮。

布局包括：场次选择、左侧手牌列表、中部快照、右侧完整事件轨迹、底部滑块及播放控制。

| 数据 | 用途 |
| --- | --- |
| `hand.events[index]` | 当前事件类型、街道、时间、行动文字 |
| `event.snapshot.players` | 该步执行后的筹码、投入、弃牌和全下状态 |
| `event.board` | 该事件时已发的公共牌 |
| `hand.results` | 事后底牌与牌型 |
| `hand.pots` / `finalPot` | 主池、边池与最终底池 |
| `hand.burned` | 事后烧牌信息 |
| 该手 `finalPlayers` | 对应这手实际人物身份，避免补位造成错配 |

`SetReplay()` 改变事件索引；首步、末步、上一/下一步、轨迹列表和滑块共用同一逻辑。播放使用单独的 DispatcherTimer，约 950 ms 一步。

“显示所有底牌”属于事后观察权限，不会重算当时的 AI 决策。悬停玩家结果可高亮公共牌中的成牌部分，点击玩家可选择其底牌高光。

维护时不要从当前场次状态推测历史底池，也不要把当前座位名字直接套在所有历史手牌上。

## 7. 声音与音乐

`Audio.cs` 使用 WPF MediaPlayer 播放本地 MP3，按轮次洗牌的队列控制音乐，并尽量避免一轮结束后立刻重复同一首。

筹码声音按“本次投入 / 行动前底池”选择：小于 33%、33%–75%、大于 75%；全下优先。快速机器人收尾事件跳过相应声音。

原项目没有文档中描述的男女 AI 行动语音缓存。当前优先查找 `assets/voices/male`、`assets/voices/female`，文件名为 `fold/check/call/bet/raise/allin.mp3`；缺失时尝试 Windows 中文语音，失败时静默。倒计时/部分牌面提示目前使用系统提示音，尚未完全复刻旧版的专用音效与动画。

美术和音频验收不能只依赖无声自动测试。实际听感、音量平衡和多设备行为仍需人工检查。
